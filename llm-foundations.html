How LLMs Generate a Response

Follow your prompt through a large language model step by step — from raw text to the words appearing on your screen.

1 Tokenization

Your text becomes tokens

The model breaks your prompt into smaller pieces called tokens — roughly word-sized chunks, subword fragments, or punctuation marks. Each token is mapped to a number using a fixed vocabulary. This converts human-readable text into a sequence of numbers the model can work with.

2 Embedding

Each token gets a position in meaning-space

Each token number is converted into a vector — a long list of values that represents what that token means. Tokens with similar meanings end up with similar vectors. At this stage, each token's meaning is context-free: the model doesn't yet know how the words relate to each other in this particular sentence.

Adding word order

Attention (Step 3) compares tokens with each other but has no built-in sense of order. Without extra information, "The dog bites the man" and "The man bites the dog" would look identical to it: same five tokens, same embeddings. So the model also injects position information, which lets attention tell tokens apart by where they appear.

Thepos 0 ␣dogpos 1 ␣bitespos 2 ␣thepos 3 ␣manpos 4 The dog did the biting.
Thepos 0 ␣manpos 1 ␣bitespos 2 ␣thepos 3 ␣dogpos 4 The man did the biting.

The original Transformer (Vaswani et al., 2017) added a fixed pattern of sine and cosine waves to each embedding. Most current LLMs use rotary position embeddings (RoPE), which encode position inside the attention calculation itself. Either way, attention can tell where each token sits in the sequence.

3 Attention

The model reads context through attention

Each token compares itself with the tokens that came before it and calculates how relevant each one is. This is called attention. In chat models attention is causal: a token can look back at earlier tokens but never ahead, because during generation the later tokens don't exist yet. Each transformer layer pairs attention with a feed-forward network that further transforms every token's vector, and models stack dozens of these layers. Research suggests earlier layers tend to capture local and grammatical patterns while later layers capture broader meaning, though the division is not clean.

How layers reshape meaning

Each layer updates every token's vector: attention mixes in information from earlier tokens, and the feed-forward network transforms the result. ⚠ Constraint

The context window limits what the model can see

The context window is the maximum number of tokens the model can process at once. It covers your prompt, any earlier conversation, and the response being generated. Anything outside the window is invisible to the model, which limits what it can understand and respond to.

Window size (tokens)

Window sizes are scaled down to fit this short passage, and each word counts as one token for simplicity. Current models handle 128,000 tokens or more, and some exceed 1 million.

4 Predict & Repeat

Next-token prediction and the coherence loop

After the transformer layers have built context-aware representations, the model uses them to predict what comes next, one token at a time.

Next-token prediction

The model takes the vector at the last position and passes it through a final layer that produces a score for every token in its vocabulary (about 100,000 for cl100k_base). A softmax function turns those scores into probabilities. The model picks one token (see Step 5), appends it to the sequence, and runs again. The response is built one token at a time, left to right.

Each new token attends to the entire sequence so far, but the model doesn't recompute everything from scratch. It stores the attention keys and values of earlier tokens in a KV cache, so each step only processes the newest token.

Coherence through the loop

There is no separate editing pass during generation. Coherence comes from conditioning each prediction on the entire sequence so far: the prompt plus every token generated up to that point. Think of writing a sentence word by word, where each word you choose is shaped by everything you've already written.

Some newer models generate reasoning text before their final answer. This lets them work through a problem step by step, but it uses the same token-by-token loop.

Where the predictions come from

Every vector, attention pattern, and probability in this guide comes from the model's learned weights. In pretraining, the model adjusts those weights by predicting the next token across a very large body of text. In fine-tuning, including instruction tuning and reinforcement learning from human feedback (RLHF), it learns to follow instructions and respond helpfully. During generation the weights stay fixed. The model uses your conversation as context but does not update its weights from it.

5 Sampling

How the model chooses the next token

The model doesn't always select the highest-probability token. Three controls shape the selection: temperature, Top-K, and Top-P. This is why the same prompt can yield slightly different responses each time.

Prompt: "The cat sat on the …"
Temperature

Reshapes the distribution. Low values sharpen it (confident, repetitive). High values flatten it (creative, chaotic). Acts on all tokens. Near 0 it becomes greedy decoding: always the top token.

Top-K

Keeps only the K most likely tokens and discards the rest. Simple hard cutoff. K=5 means only 5 candidates survive.

Top-P

Keeps the smallest set of tokens whose combined probability ≥ P. Adapts dynamically — sometimes 3 tokens, sometimes 8, depending on how confident the model is.

The controls apply in order: temperature first, then Top-K, then Top-P. The remaining probabilities are then rescaled to add up to 100%.

6 Output

Detokenization and delivery

Each generated token is still a number. It needs to become text on your screen.

Detokenization

The tokenizer, a separate component from the neural network, reverses the lookup from Step 1. It converts token IDs back into text fragments and joins them. For example, token IDs [16047, 38, 2898] become ["Chat", "G", "PT"], which join to form "ChatGPT". Some tokens hold only part of a character (common with emoji and non-Latin scripts), so that character appears once all of its pieces have arrived.

Streaming the output

The text is streamed to your screen token by token as it is generated, which is why responses appear a few words at a time. The model doesn't write the full response before sending it. What you see is the output as it is produced.
